# 아파트 실거래가 예측

국토교통부 실거래가(공공데이터포털 오픈API)를 받아, 원하는 아파트의 **현재 추정 시세**와 **1~3년 뒤 가격 범위**를 보여주는 로컬 웹앱입니다. Python 표준 라이브러리만 쓰므로 별도 설치가 없습니다.

## 실행

```bash
cd apt-price
cp .env.example .env      # .env 를 열어 MOLIT_SERVICE_KEY= 뒤에 인증키 입력
python3 server.py         # 브라우저에서 http://127.0.0.1:8000
```

- 인증키 없이 실행하면 **가상 데이터(데모)** 로 화면만 확인할 수 있습니다.
- 인증키: data.go.kr 에서 "국토교통부 아파트 매매 실거래가 상세 자료" 활용신청 후 발급되는 일반 인증키(Encoding/Decoding 모두 가능).
- 포트 변경: `PORT=9000 python3 server.py`

## 사용법

1. 지역(시·군·구)을 입력해 선택합니다. 처음 선택한 지역은 최근 10년(120개월)치를 받아 `data/cache.db` 에 저장하며, 다음부터는 최근 3개월만 갱신합니다.
2. 아파트 이름을 검색해 선택하고, 평형(전용면적)을 고릅니다.
3. 현재 추정 시세, 1·2·3년 뒤 예측과 80% 구간, 실거래 차트, 최근 거래 목록이 표시됩니다.

분석 기간은 최근 10년이며, 그보다 늦게 입주한 단지는 입주 이후 거래만 있으므로 자동으로 입주년도부터 분석됩니다.

## 예측 방법 (`model.py`)

| 항목 | 계산 |
|---|---|
| 지역 지수 | 시군구 전체 거래의 ㎡당 가격 중위값(직전 3개월 묶음) |
| 특이 거래 제외 | 같은 단지·평형의 앞뒤 6개월 거래(지역 지수로 시점 보정)와 25% 넘게 차이 나는 거래. 차트에 회색 원으로 표시하고 계산에서 뺌 |
| 현재 추정 시세 | 선택 평형의 최근 12개월 거래(3건 미만이면 24·36개월·전체로 확대)를 지역 지수로 현재 시점에 맞춰 보정, 최근 거래에 가중(반감기 6개월) |
| 예측 중심값 | 향후 1년은 지역의 최근 12개월 시세 변화율(연 -10% ~ +12% 로 제한) 적용. 1년 이후는 방향을 예측하지 않고 1년 뒤 수준 유지 |
| 예측 구간(80%) | 지역 지수의 과거 1년 변동성 + 단지 내 거래가 편차로 기본 폭 계산 |
| 구간 보정 | 지역 내 거래가 많은 단지·평형(최대 80개)의 과거 검증 오차를 1·2·3년 기간별로 모아, 80% 구간이 실제로 80%를 덮도록 폭에 배율을 곱함. 단지 자체 오차가 크면 더 넓힘. 좁히는 방향으로는 쓰지 않음 |
| 검증 | 과거 6개월 간격 시점마다 같은 방법으로 예측해 실제 거래와 비교한 평균 오차·구간 적중 횟수 |

해제된 거래는 제외합니다. 층·동·향 차이는 따로 보정하지 않고 구간 폭에 반영됩니다.

### 실데이터 검증 결과 (2026-11, 마포구·해운대구 각 10년치)

| | 마포구 | 해운대구 |
|---|---|---|
| 1년 뒤 예측 평균 오차 | 12.0% | 16.9% |
| 80% 구간 적중, 보정 전 (1년) | 65% | 57% |
| 80% 구간 적중, 보정 후 (1년 / 2년 / 3년) | 85% / 86% / 88% | 83% / 86% / 81% |
| 특이 거래로 제외된 비율 | 0.7% | 2.9% |

구간 적중은 배율 계산에 쓰지 않은 단지들에서 잰 값입니다.

모델을 이렇게 정한 근거:

- **1년 이후는 방향을 예측하지 않음**: 추세를 3년까지 연장하던 이전 방식은 3년 뒤 오차가 "가격 변화 없음" 가정보다 컸습니다(마포구 28% 대 19%, 해운대구 35% 대 22%). 1년 뒤는 최근 12개월 변화율을 쓰는 쪽이 두 지역 모두에서 가장 나았습니다. 그래도 해운대구에서는 1년 뒤 오차가 "변화 없음" 가정과 같은 수준이었습니다.
- **일괄 상향 보정은 하지 않음**: 마포구에서는 실제 가격이 예측보다 높았던 경우가 3분의 2였지만 해운대구에서는 절반이었습니다. 지난 10년 상승장의 특성이지 모델의 고정된 치우침이 아니어서 보정하지 않았습니다.

**한계**

- 과거 거래 추세만 쓰므로 금리·정책·공급 같은 외부 요인과 시장 전환점은 맞히지 못합니다. 1년 뒤 예측도 평균 12~17% 빗나갑니다.
- 구간 배율은 지난 10년의 실적에 맞춘 값이라 시장 국면이 바뀌면 달라집니다.
- 조망·층에 따라 가격 차가 큰 단지에서는 정상 거래가 특이 거래로 분류될 수 있습니다(해운대구의 제외 비율이 높은 이유로 추정).
- 특이 거래 판정에는 앞뒤 6개월 거래를 쓰므로, 과거 시점 검증 수치에는 그 시점 이후의 정보가 약간 섞여 있습니다.

## 알아둘 점

- 실제 API로 확인한 내용(2026-11): 응답 태그·해제 거래(`cdealType` = `O`)·페이지 나누기·인증키 전달, 한 구(서울 마포구) 120개월 수집과 캐시 재사용, 실제 단지의 분석 화면. 테스트의 `tests/real_response.xml` 이 실제 응답을 줄인 것입니다. 한 달 거래가 1,000건을 넘는 경우(페이지 넘김)는 작은 페이지 크기로만 확인했습니다.
- `regions.json` 의 시군구 코드는 2026년 11월 실제 API 응답 기준입니다. API는 **현재 코드로만** 과거 거래까지 모두 돌려주고, 폐지된 코드는 오류 없이 0건을 돌려줍니다(부천시 → 원미·소사·오정구, 화성시 → 만세·효행·병점·동탄구, 인천 제물포·영종·서해·검단구, 강원 51xxx, 전북 52xxx, 군위군 27720). 이후 또 개편되면 "거래가 한 건도 없습니다" 안내가 나오며, 파일에 `{"code": "5자리", "name": "이름"}` 을 고쳐 넣으면 됩니다. 이 개편 지역 밖의 코드는 전수 확인하지 않았습니다.
- 단지는 API의 단지 일련번호(`aptSeq`)로, 평형은 전용면적의 정수 부분으로 묶습니다. 전용 59.9㎡ 와 60.3㎡ 처럼 경계에 걸친 평형은 따로 표시됩니다. 직거래·토지임대부 거래도 구분 없이 포함됩니다.
- 서버는 본인 PC(127.0.0.1)에서만 접속됩니다. `.env` 와 `data/` 는 git 에 올라가지 않습니다.
